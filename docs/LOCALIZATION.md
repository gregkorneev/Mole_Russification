# Локализация CLI Mole

Русская локализация в ветке `feature/russian-localization` относится к форку [`gregkorneev/Mole_Russification`](https://github.com/gregkorneev/Mole_Russification). Она не входит в официальные выпуски [`tw93/Mole`](https://github.com/tw93/Mole), Homebrew или официальный скрипт установки.

## Выбор языка

CLI поддерживает английский (`en`) и русский (`ru`). Выбор применяется в таком порядке:

1. Переменная окружения `MOLE_LANG` для текущего процесса и его дочерних команд.
2. Сохранённый выбор `~/.config/mole/language`.
3. Локаль macOS `AppleLocale`, затем `LC_ALL`, `LC_MESSAGES` или `LANG`.
4. Английский язык, если значение не поддерживается или не задано.

Сохранить предпочтение можно так:

```sh
mo config language ru
mo config language en
```

Чтобы выбрать язык только для одного запуска:

```sh
MOLE_LANG=ru mo --help
MOLE_LANG=ru mo analyze --help
MOLE_LANG=ru mo status
```

Настройка меняет язык интерфейса Mole и не редактирует системную локаль. Команды и параметры остаются прежними. Структура JSON, имена полей, коды действий в журналах и форматы для автоматизации не переводятся.

## Границы перевода

Переведены сообщения CLI, справка, диагностика аргументов, пункты и подсказки меню, строки статуса и текстовые сводки shell-команд, а также интерфейсы Analyze и Status на Go. История операций сохраняет исходные строки и коды действий; текстовый вывод `mo history` может показывать русские подписи, а `--json` сохраняет прежнюю структуру и значения.

Имена команд и флагов, пути, URL, идентификаторы приложений и системных компонентов, названия сторонних продуктов и вывод внешних утилит остаются такими, какими их ожидает CLI или возвращает сама утилита. Это сохраняет команды для копирования, точность диагностики и совместимость автоматизации.

## Устройство каталогов

Общие каталоги находятся в `lib/i18n/en.tsv` и `lib/i18n/ru.tsv`. Bash загружает их в процессные переменные через `lib/core/i18n.sh`; Go TUI Analyze и Status читают те же TSV-файлы через `internal/i18n`. Ключи являются стабильными идентификаторами, а английский каталог — источником резервного значения.

Добавляя строку, добавьте один и тот же уникальный ключ в оба файла. Сохраняйте форматные маркеры (`%s`, `%d`, `%.1f` и другие) в обоих значениях. Табуляция отделяет ключ от текста, поэтому используйте однострочные значения. Для новых вызовов `mole_t KEY` или `i18n.T("key")` добавьте ключи в обе локали.

## Синхронизация с оригинальным Mole

Перед обновлением ветки до `upstream/main` сначала посмотрите, что изменилось (`git fetch upstream && git diff HEAD...upstream/main --stat`), и только затем объединяйте изменения. После слияния найдите новые пользовательские строки в `bin/`, `lib/` и `cmd/`: каждая такая строка должна получить ключ в обоих каталогах. Тест `internal/i18n` проверяет, что наборы ключей и форматные маркеры совпадают, а русский текст не остался копией английского (осознанные исключения вроде названий продуктов перечислены в самом тесте). Для текста, который не должен меняться (команды, флаги, JSON, имена полей, вывод внешних утилит), ключи не нужны.

## Проверка локально

Сборка и просмотр справки не меняют установленный Mole:

```sh
make build
MOLE_LANG=ru ./mole --help
MOLE_LANG=ru ./mole clean --dry-run
```

Для проверки каталогов и интерфейсов:

```sh
go test ./internal/i18n ./cmd/analyze ./cmd/status
MOLE_TEST_NO_AUTH=1 MOLE_LANG=en bats tests/i18n.bats
```

Полная локальная проверка ветки:

```sh
./scripts/check.sh --format
./scripts/check.sh --no-format
go test ./...
TERM=xterm-256color MOLE_TEST_NO_AUTH=1 ./scripts/test.sh
make build
```

Для адресной безопасной проверки русской версии из исходного checkout, не затрагивая установленный `mo`:

```sh
MOLE_LANG=ru MOLE_TEST_NO_AUTH=1 ./mole clean --dry-run
```

Запускайте Bats из checkout вне `~/Desktop`, например из `~/src/Mole_Russification`. Наблюдение на macOS 27: внутри `~/Desktop` каталог `.Trash`, который тесты создают во временном `HOME`, исчезает через 1–2 секунды без участия Mole (в `~/.cache` он остаётся), поэтому `real direct Trash sink` в `tests/uninstall_timeout.bats` падает нестабильно, в том числе на неизменённом `HEAD`.

`make build` собирает локальные артефакты проекта. Не запускайте `install.sh`, `mo update` или команды очистки без `--dry-run`, если хотите лишь проверить перевод в исходном checkout.
